> 只出设计，未改任何代码。核实来源写在每一条判断后面（`client.js:行号`）。
> 承现有语言：`.wt-desk` / `.wt-card` / `.wt-pill` / `.wt-dot` / `.wt-avatar-wrap` 状态环 / `wt-sparkle`。

## 0. 先修正三条事实（读完代码后的偏差）

| 说法 | 实际 | 依据 |
|---|---|---|
| 工位卡网格 3 列 | **4 列**。`@media (max-width:760px)` 才降 2 列 | `client.js:329` `repeat(4,minmax(0,1fr))`；`:421` |

| 交接已有视觉 | **不存在**。`previousTasks` 只比较 `in_progress → completed`，触发的是「完成」sparkle，**不比较 `ownerName`** | `client.js:2058-2073` |

第三条第 3 点是这次设计真正要补的空：A 把任务转给 B，现在屏幕上只会看到 B 那行的任务文字换了，没有任何「交接」的表达。

- `.wt-btn.primary` 是 `background: brand-primary; color:#fff`（`client.js:308`）。`brand-primary` 在暗色是近白，`#fff` 白字 —— 暗色主题下这是白底白字。`#fff` 同样是硬编码。修法：`color: var(--dsw-alias-label-primary-inverted)`（`.wt-seat-send` 已在用，`client.js:386`）。

## 1. 盒子：侧边栏给我们的可用宽度

已核实的三条硬事实：

1. 右侧栏最窄会被压到 **300px**（框架为保护中栏 400px，先把右栏压到 300，再报「空间不足」让占位方关掉）—— `dsh-client-ui-layout` README。
2. 面板「取会话区底色与正文字号，**是页面的一列，不是压在页面上的卡片**」—— `dsh-client-ui-sidebar-right` README。
3. tab 条就是面板的整条上边（tab 胶囊、添加、分栏、形态控件都在里面）—— 同上。

由此三条推出三个决定：

- **不要再套 `.wt-modal` 那层壳**：16px 圆角 + `bg-overlay` + 28% 阴影（`client.js:316`）在侧边栏里会变成「卡片里的卡片」，和「一列」的定位冲突。正文直接用面板底色，只保留分隔线。
- **正文里不要再放二级 tab**：`.wt-tabs`（`client.js:325-327`，padding 8 + tab 高约 30）省掉 38px，两个 tab 应该注册成两个 `sidebar.right.pane.tab` 类型。
- **正文左右内距收到 10px**（现状 `.wt-modal-body` 是 `14px 18px 18px`，`client.js:328`）。18×2 = 36px，在 380px 栏里是 9.5% 的宽度，在 300px 栏里是 12%。

宽度预算：

| 栏宽 | 内容宽（减 20） | 场景 |
|---|---|---|
| 560 | 540 | 用户拉宽 / 全屏 |
| 380 | 360 | 首次打开的常见宽度 |
| 320 | 300 | 用户拉窄 |
| 300 | 280 | 框架下限 |

## 2. 三个方向

三个方向的总高差只有 120px（384 / 408 / 264–424），**所以差异不在密度**，在于：谁是主信号、员工位置稳不稳、用户扫的是「人」还是「事」。

### 方向 A · 工位列表

**一句话：值班表，不是办公室 —— 一列人对齐成一条状态轴。**

```
栏 380，内容 360，左右内距各 10
┌────────────────────────────────────────┐
│ 团队 8/8    干活 3 · 等你 1        28  │ ← 组头，sticky
├────────────────────────────────────────┤
│ (28) 小前                  ● 干活中  44 │
│      前端 · 改登录页的错误提示…          │
├────────────────────────────────────────┤
│ (28) 小设                  ● 等你回复 44 │
│      设计 · 等你回一句「哪个方向」       │
├────────────────────────────────────────┤
│ (28) 阿策                  ○ 待命    44 │
│      产品 · 等待派活                     │
├────────────────────────────────────────┤
│ (28) 笔笔                  + 空位    44 │
│      文案 · 说「招」                     │
└────────────────────────────────────────┘
行高 44 = 7 + 16（名字 12px/600）+ 14（次行 11px）+ 7
8 人 = 8×44 + 7×0.5px 分隔线 ≈ 356；加组头 28 → 384
```

**状态表达**

| 通道 | 规格 | 作用 |
|---|---|---|
| 头像环（主） | 28px 头像，`::after` 收到 `inset:-2px; border:1.5px`（现有 44px 头像是 -3px/2px，28px 上照搬会显得糊） | 颜色 + 动效，唯一零水平成本的通道 |
| 右对齐状态列（次） | 固定 56px，`margin-left:auto`，4 字 + 8px 间距 + 环 | 8 行文字右边缘对齐成一条竖线 —— **这是 A 的核心视觉：扫一列，不扫每行** |
| 小圆点 | **删** | 与环语义完全重复，还占 10px 横向 |
| 胶囊 | **删** | 2px 描边 + 7px 内距 = 16px 横向成本，换 0 新信息 |

**动效清单**

| 触发 | 动效 | 时长 | 曲线 |
|---|---|---|---|
| 进入 working | 环切 business + 头像 bob | 环 160ms；bob 1150ms 无限 | ease-out；ease-in-out |
| 进入 waiting | 环切 warn + 头像 wait 摆动 | 160ms；1800ms 无限 | ease-out；ease-in-out |
| 进入 done | 环切 success 实心亮 | 160ms | ease-out |
| 任务完成 | 行尾 ✦ 播一次 | 1300ms | ease-out（沿用 `wt-sparkle`） |
| hover | 行底 `interactive-bg-hover` | 120ms | ease-out |
| 键盘 focus | 左缘 2px business 竖条（复用 `.wt-dispatch-row.active::before` 的写法，`client.js:402`） | 瞬时 | — |
| 交接 | 见 §3 候选 2 | — | — |

**窄栏塌缩（320 → 内容 300）**

| 元素 | 380 | 320 |
|---|---|---|
| 行高 | 44 | 44（不变） |
| 头像 | 28 | 28 |
| 状态列 | 56（4 字全称） | 只留环；文案 `@container` 隐藏，`title` 兜底 |
| 次行 | `角色 · 任务` | 角色段隐藏，只留任务（名字列剩 300−28−8−20 = 244px，不截断） |

**A 的硬优点：没有需要塌缩的结构。** 320px 下唯一变化是两处 `display:none`。

**为这个取舍主动放弃的**

- 放弃 B 的 40px 头像：44px 行高里塞 40px 头像只剩 2px 呼吸空间，头像缩到 28 已经够认（角色 palette 的 accent + 名字），再大是「卡」的思路。
- 放弃 B 的桌面色带：在行形态里它只能变成 2px 的色线，纯装饰、不携带信息，只会和状态环抢颜色。
- 放弃 C 的分组：分组意味着员工位置随状态跳。A 里「小设」永远第 2 行，是肌肉记忆；C 里他会在 4 个组之间跳，每次都要重新找。**这是 A 与 C 最本质的取舍，不是密度。**

### 方向 B · 微型工位卡

**一句话：还是办公室 —— 每人一张桌子，桌面色认人，头像占主导。**

```
栏 380，内容 360，2 列，列距 8，卡宽 176
┌──────────── 176 ───────────┐ ┌──────────── 176 ───────────┐
│ (40) 小前              ●   │ │ (40) 小设              ●   │ ← 头像行 40
│      前端                  │ │      设计                  │ ← 角色 14
│      改登录页的错误提示…    │ │      等你回一句…           │ ← 任务 14（1 行）
│▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔│ │▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔│ ← 桌面色带 8
└────────────────────────────┘ └────────────────────────────┘
卡高 96 = 10 + 40 + 4 + 14 + 3 + 14 + 8 + 3
4 行 × 96 + 3 × 8 = 408
```

**状态表达**

| 通道 | 规格 | 作用 |
|---|---|---|
| 头像环（主） | 40px 头像，沿用 `inset:-3px; border:2px` | 颜色 + 动效 |
| 名字行 5px 圆点（次） | 沿用 `.wt-dot`，切正确 token | 卡宽 176 放不下 4 字文案，点是最省的补充 |
| 桌面色带 | 8px，`accent 18% + bg-layer-2`。现有 `.wt-desk::before` 是 26px / `accent 10% + bg-layer-1`（`client.js:290`）—— 8px 高时 10% 混色几乎看不见，要提到 18% | **身份色，不是状态色**。状态只在环 + 点 |
| 任务文案 | 1 行（现有 2 行 clamp 要收，卡只给 14px） | — |

**动效清单**

| 触发 | 动效 | 时长 | 曲线 |
|---|---|---|---|
| tab 首次可见 | 逐卡 `opacity` + `translateY(4px)`，stagger 24ms/张 | 200ms | ease-out |
| 进入 working | 环 pulse + 头像 bob | 1500ms 无限；1150ms 无限 | ease-in-out |
| 进入 waiting | 环切 warn + pulse + 「?」气泡 | 1000ms；气泡 1100ms | ease-in-out |
| hover | 描边切 business + `translateY(-1px)` | 150ms | ease-out（沿用 `.wt-card`，`client.js:258`） |
| 完成 | ✦ 播一次 | 1300ms | ease-out |
| 交接 | 见 §3 候选 2 | — | — |

**窄栏塌缩（320 → 内容 300）**

| 元素 | 380 | 320 |
|---|---|---|
| 列数 | 2（卡 176） | **保持 2**（卡 146） |
| 头像 | 40 | 32 |
| 任务文案 | 1 行 | 隐藏，`title` 兜底 |
| 卡高 | 96 | 84 |
| 桌面色带 | 8 | 6 |
| 总高 | 408 | 8×84 + 7×8 = 728（8 人 → 4 行 2 列 = 4×84+3×8 = 360，实际不滚动） |

**为什么塌缩选「保 2 列收头像」而不是「切 1 列」**：切 1 列后 8 人 = 8×72 + 56 = 632px，必须滚动。「一眼看到全队」是这个面板唯一的承诺，滚动会破坏它；而 146px 里放 32 头像 + 3 个汉字是够的（「小前」「阿策」「笔笔」都是 2 字）。

**为这个取舍主动放弃的**

- 放弃 A 的右对齐状态列：176px 卡里，状态列要 56px，剩 120px 给 40 头像 + 名字 = 名字只剩 72px。更致命的是 4 字文案在 176px 卡里必须换行或省略，省略成「干活…」比环 + 点更难读。所以 B 的状态必须回落到「环 + 点」，这正好是 B 放弃 A 状态列的理由。
- 放弃 C 的分组：C 里每组只有 1–3 张卡，组头 26px + 1 张 96px 卡 = 122px 换 1 个人，密度崩掉（4 组组头 104px 占 408 的 25%）。

### 方向 C · 楼层 / 泳道

**一句话：看板 —— 不问「谁在忙」，问「我该先回谁」。**

```
栏 380，内容 360
┌────────────────────────────────────────┐
│ 等你回复  1                        26  │ ← 组头，warn 文字，永远置顶
│ (28) 小设 · 设计        哪个方向？   40  │
├────────────────────────────────────────┤
│ 干活中  3                          26  │
│ (28) 小前 · 前端        改登录页…    40  │
│ (28) 老后 · 后端        迁移脚本…    40  │
│ (28) 小研 · 研究员      竞品调研…    40  │
├────────────────────────────────────────┤
│ 待命  3                        ⌄   26  │ ← 默认折叠
├────────────────────────────────────────┤
│ 已完成  1                      ⌄   26  │ ← 默认折叠
└────────────────────────────────────────┘
常态（2 展开 + 2 折叠）= 26+40 + 26+120 + 26 + 26 = 264
全展开 8 人 = 4×26 + 8×40 = 424
```

**状态表达**

| 通道 | 规格 | 作用 |
|---|---|---|
| 组头（唯一状态信号） | 状态色文字 + 计数，26px | 状态是结构，不是标记 |
| 行内头像 | 28px，**去掉状态环** | 状态已由组头说明，行内再上色是双重编码 |
| 空组 | 整组不渲染 | 「待命」在全员忙时消失，不占位 |
| 「等你回复」组 | 永远第一，组头左侧 2px warn 竖条呼吸 | 这是唯一需要用户动作的组 |

**动效清单**

| 触发 | 动效 | 时长 | 曲线 |
|---|---|---|---|
| 员工换组 | 旧位置行淡出 + 高度收 0；新位置行从 0 展开 + 淡入 | 各 160ms（合计 320ms） | ease-in / ease-out |
| 组计数变化 | 数字交叉淡入 | 120ms | ease-out |
| 「等你回复」新增 | 组头竖条呼吸 | 1000ms 无限 | ease-in-out |
| 折叠/展开 | `max-height` 过渡 | 180ms | ease-out |
| 交接 | 见 §3 候选 2 变体 | — | — |

**窄栏塌缩（320 → 内容 300）**

| 元素 | 380 | 320 |
|---|---|---|
| 组头 | 26 | 26 |
| 行高 | 40 | 40 |
| 行内角色段 | 显示 | 隐藏（只留名字 + 任务） |
| 结构 | — | **零变化** |

**为这个取舍主动放弃的**

- 放弃 A 的固定行位：C 的核心就是位置随状态变。保留固定行位等于放弃分组，两个不能同时要。
- 放弃 B 的大卡：理由同 B 小节最后一段（组头占比 25%）。
- 放弃「组内也上状态色」：组已经说明了状态，行内再上色会让「等你回复」组变成「1 个黄组头 + 1 个黄环」，一片黄；而且它会让 C 失去「组头是唯一信号」这个清晰度。

### 三方向对照

| 维度 | A 列表 | B 微卡 | C 泳道 |
|---|---|---|---|
| 8 人总高（栏 380） | 384 | 408 | 264–424 |
| 栏 320 退化 | 两处 `display:none` | 头像 40→32、藏任务文案 | 一处 `display:none` |
| 头像 | 28 | 40 | 28 |
| 主信号 | 右对齐状态列 | 头像环 + 点 | 组头 |

| 扫「谁在等我」 | 逐行看 | 逐行看 | 一眼（置顶组） |
| 扫「某人现在怎样」 | 一眼（固定行） | 一眼 | 要跨组找 |

## 3. 「交付 / 交接」动画怎么做

先钉触发面。四条都会在界面上发生，现状只有第 2 条有反馈：

| 事件 | 现状 | 该有什么 |
|---|---|---|
| 任务板 `ownerName` A→B | **无任何视觉** | 交接反馈 |
| 任务板 `status` in_progress→completed | ✦ sparkle（`client.js:2058-2073`） | 保留 |
| A 的 `working`→`idle` | 环变色 | 已有，够 |
| B 的 `idle`→`working` | 环变色 + bob | 已有，够 |

### 候选 1 · 两端各自变，不画路径（纯 CSS）

**用户看到**：A 那行的任务串换成「→ 小前」1600ms 后淡出回「等待派活」；B 那行的任务串从左侧 4px 滑入；B 的头像环 160ms 从 idle 灰过渡到 business 蓝。

**实现代价**：纯 CSS。一个 `transition` + 一个 `@keyframes` + 一个瞬态 class。瞬态标记可以直接照抄 `flashSparkle` 的 Set + 1300ms 清理模式（`client.js:564-578`）。

**缺点**：没有方向感。A 和 B 不在同一屏时，用户只看到 B 变了，不知道从哪来。

### 候选 2 · 两行各被「点名」一次（需要 0 次 DOM 测量）

**用户看到**：B 行底色从 `interactive-bg-active` 480ms 线性褪回透明；A 行底色从 `interactive-bg-hover` 同样褪回；B 的头像环同时 pulse 一个周期（1500ms）。任务板 tab 若正开着，对应任务卡描边从 business 480ms 褪回 `border-l2`。

**实现代价**：纯 CSS。唯一需要判断的是「目标行在不在视口」——8 人在 384px 里、栏高通常 600px 以上，**基本都在**；万一不在，用 `scrollIntoView({block:'nearest'})`，那是滚动不是测量。**所以这个候选实际代价等于候选 1。**

**我推荐它**，因为它同时表达了「两边都变了」和「这两行是一件事」，而成本没涨。

### 候选 3 · 幽灵卡片飞行（需要 JS 逐帧）

**用户看到**：A 的卡克隆一份，`position:fixed`，沿贝塞尔飞 240ms 到 B 的位置，边飞边缩到 0.6。

**实现代价**：最高。要 portal 到 body（否则被面板 `overflow` 裁）、要处理侧边栏滚动 / resize 时坐标失效、飞行中 A 或 B 可能因 tab 切换被卸载、reduced-motion 要另写「直接消失」。

**否掉它的理由不是难度，是尺度**：栏只有 300–380px 宽，一张 176px 的卡在这么窄的列里横飞 200px，视觉上是「撞墙」而不是「传递」。

### 采用方案：候选 2 为主，候选 1 作为不可见时的降级

```
t=0    B 行底色 → interactive-bg-active，480ms 线性褪回
t=0    B 头像环 → business，160ms 过渡；pulse 一个周期 1500ms
t=0    A 行底色 → interactive-bg-hover，480ms 褪回
t=0    A 行尾「→ 小前」320ms 淡入，1600ms 后淡出（沿用 dispatch 成功的 1600ms 停留语汇）
t=0    任务板对应卡描边 → business，480ms 褪回 border-l2
```

**`tab.visible === false` 时**（`useTabInfo()` 提供，sidebar-right README §84）：不播动画，把「A 行 → 小前」这个标记保留到下一次可见，静态显示 1600ms。依据：用户不在看的时候播动画等于白播，而交接信息不能丢。

**reduced-motion**：取消全部 480ms 过渡。只保留 A 行的「→ 小前」文字标记（1600ms），B 行不做底色 —— 瞬时变色再瞬时变回等于闪一下，比不做更糟。

## 4. 状态指示色的分层：留几个

现状 4 处：头像环、5px 小圆点、胶囊标签、状态文案（`client.js:274 / 265 / 296 / 991`）。

**结论：留 2 处 —— 头像环（主）+ 状态文案（次）。删小圆点。胶囊按方向处理。**

依据：

1. **环是唯一零水平成本的通道。** `inset:-3px` 画在头像外，不参与布局宽度。380px 栏里每 1px 水平空间都要买，所以主信号必须落在不占宽度的通道上。
2. **环同时承载颜色 + 动效，这是 7 个状态能挤进 5 个色的唯一办法。** 状态有 provisioning / idle / working / waiting / done / error / failed 七个（`client.js:514-521`），色只有五个：灰 / business 蓝 / warn 琥珀 / success 绿 / error 红。provisioning 和 working 共用蓝，靠 `dashed + spin` 与 `pulse` 区分（`client.js:273-274`）；failed 和 error 共用红，靠文案区分。**没有动效，provisioning 和 working 在视觉上就是同一个状态。**
3. **颜色不能是唯一通道。** working 的 business 蓝和 error 的红，在红绿色盲下都读作「暗色块」；done 的绿和 warn 的琥珀在黄绿色盲下接近。所以状态文案必须在，它是 reduced-motion 和色觉差异下唯一的可靠通道。
4. **小圆点必须删。** 它 5px，只靠颜色、没有形状差异、没有动效，是四个通道里最脆弱的一个，却和环语义完全重复。删掉省 5+5=10px 横向。
5. **胶囊**：A 方向删（状态文案已右对齐成列，胶囊的 2px 描边 + 14px 内距 = 16px 横向换 0 新信息）；B 方向保留但改成**无描边纯文字**（省 2px 描边 + 内距 7→0，只靠颜色）。
6. **320 栏的状态文案**：默认隐藏，靠 `title` 兜底（现有 `title` 已含状态，`client.js:975`）。但 `@media (hover:none)` 下要保留 —— 触屏没有 hover，隐藏文案等于删掉唯一通道。这条组合条件 CSS 能写，不需要新增 locale key。

## 5. 必须顺手修的状态色 bug

`brand-primary` 是**结构色**（亮色近黑 / 暗色近白），不是**状态色**。用于按钮填充是对的（`.wt-btn.primary` 黑底白字 = 主按钮），用于状态是错的。

| 位置 | 现在 | 应为 | 视觉后果 |
|---|---|---|---|
| `.wt-dot.working` / `.provisioning`（:265） | brand-primary | `state-business-primary` | 亮色下是近黑点，与 idle 灰点只差明度，「在忙」看不出来 |
| `.wt-avatar-wrap.st-working::after`（:274） | brand-primary | `state-business-primary` | 环是近黑，与 idle 灰环对比不足，pulse 变成「灰环明暗呼吸」 |
| `.wt-avatar-wrap.st-provisioning::after`（:273） | brand-primary | `state-business-primary` | 与 working 完全同色，只能靠 dashed 区分 |
| `.wt-pill.working` / `.provisioning`（:296） | brand-primary | `state-business-primary` | 胶囊文字近黑，与默认 `label-secondary` 只差一点，等于没上色 |
| `.wt-spinner` 的 `border-top-color`（:361） | brand-primary | `state-business-primary` | 语义是 loading，用近黑不准确 |

`.wt-bubble` 的修法（`client.js:287`，`color:#241a00` 是 hex）：

改成**描边式** —— 底 `bg-layer-3`、0.5px 描边 `state-warn-primary`、文字 `state-warn-primary`、`font-weight:700`。理由：实心琥珀在暗色主题下是个亮黄块，在 380px 的深色侧边栏里会变成最强视觉元素，而它只是「等你回复」的提示，不该比头像亮。这样也彻底不需要 hex。

**技术前提（不满足则上面整张表落空）**：必须用 `@container`，不能用 `@media`。侧边栏变窄时**窗口宽度不变**，媒体查询不会触发。现有代码只有 `@media (max-width:760px)`（`client.js:420`），那条在侧边栏里会误判（窗口 1600px、侧边栏 320px，它会认为「屏幕很宽」）。

## 7. 动效语汇与 reduced-motion

新增时长全部落在既有网格上（不引入新值）：

| 值 | 来源 |
|---|---|
| 120ms | `.wt-dispatch-in` / hover（已有） |
| 160ms | 新增：环切色、行入场 |
| 320ms | `wt-hands` 半周期（已有） |
| 480ms | 新增：交接底色褪去 |
| 1300 / 1400ms | `wt-sparkle` / sparkle 清理（已有） |
| 1500 / 1800 / 2400 / 4200 / 5400ms | 环 pulse / wait / spin / breathe / blink（已有） |
| 1600 / 2400ms | dispatch 成功 / 失败停留（已有） |

曲线只用既有的四种：`ease-out`、`ease-in`、`ease-in-out`、`linear`。

`prefers-reduced-motion` 块（`client.js:427-431`）要并进新选择器：`.wt-row`、`.wt-row-flag`、`.wt-tile`、`.wt-lane`、`.wt-lane-head`、`.wt-hl`。降级规则：交接只留文字标记，不做底色；逐卡 stagger 取消（直接出现）；折叠/展开瞬时。
