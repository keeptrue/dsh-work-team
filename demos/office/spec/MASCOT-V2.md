## 0. 一句话定位 + 推荐

| 套 | 一句话 | 定位 |
|---|---|---|
| **S1 平面剪影 + 屏幕光** | 一种墨色，只有「光」是渐变 | Marvis 路线。32px 最稳，暗色最省事，实现最便宜 |
| **S2 软陶质感** | 三档同色系 + 高光点 + 更大的头 | 最可爱，但 32px 优势消失，暗色要单独压高光 |
| **S3 线描淡彩** | 1px 墨线 + 角色色淡彩填充 | 最有性格，但 32px 细线糊成灰边，实现最贵 |

**推荐 S1。** 理由只有一条是决定性的：**32px 是验收尺寸，而 32px 只奖励剪影和色块，不奖励质感和线条。**
S2 的渐变在 32px 下等于不存在（实测见 §5：S1 与 S2 的 32px 差异表几乎一样），S3 的 1.1 单位描边在 32px 下是 0.55px —— 浏览器会把它渲染成一层灰雾，把淡彩吃掉。也就是说：S2/S3 的"好看"只在 48px 以上兑现，而工位常态是 32–46px。

S1 在 96px 下也不寒酸：它的高级感来自「一侧轮廓光 + 屏幕色落在身上」，不是来自质感。这正是 Marvis 的做法，也是它能在小尺寸站住的原因。

## 1. 逐条对着四个丑点改

### ① 没有家具，只有白底浮着猫和电视

`furniture-v2.svg` 把「一格工位」当成一个小场景画，并给出**图层契约**（前端照这个顺序拼，不要整块塞）：

```
z0 #u-floor      地面线 + 接触阴影
z1 #u-chair      椅背（角色身后，只露两侧圆弧）
z2 #u-monitor    外框 / 屏幕 / 支架 / 底座 / 落地阴影

z4 角色          50×56
z5 #u-deskfront  桌面 + 2px 前沿线  ← 压在角色身上

```

**关键的一层是 z5。** 角色被桌面压住 8px，才叫"坐在桌前"；不压就是"站在桌子前面"。03:04 版的问题是角色和桌子之间没有遮挡关系，所以两者是两张贴纸。

### ② 角色是一坨近黑剪影

拆成 5 个可辨认部件，每个都有独立作用：

| 部件 | 规格 | 为什么需要 |
|---|---|---|
| 头 | 34×32 单位（显示 26.5×25px），**占角色宽度的 53%** | 03:04 版头只占 36%，所以像"头下面接了个方块" |
| 耳 | 6 种：尖猫 / 折耳猫 / 垂耳狗 / 短圆狗 / 立耳狗 / 高狐 / 短狐（带浅色耳尖） | 同 species 也要能分（§4） |
| 项圈 + 铭牌 | 横跨颈部，**把脖子压住 2px**；8 种铭牌形状 | 身份色唯一的落点 |
| 身 | 30 高（头 32）＝ **1 : 0.94**；三种宽度 std / bulky / slim | 头身比是"可爱"的主要来源 |
| 前爪 | 两个圆凸在桌沿，比身体亮 52% 混纸色，透明度 .55 | 有爪子搭在桌上，人才是"在工位里" |

03:04 版的项圈是「一块彩色梯形贴在胸口」，现在是「一条带子横跨脖子 + 一颗铭牌垂下」—— 因为有了脖子这个结构，项圈才有地方可系。

## 2. 角色被屏幕光照到：具体做法

**原理**：光不是"给角色加个滤镜"，而是**同一个剪影画第二遍，用屏幕色的世界坐标渐变填充**。

```
1. 剪影第一遍   fill = 墨色                       ← 形体
2. 光层         fill = url(#gLight)  opacity .55   ← 光落在身上
3. 轮廓光       stroke = 白 .26，clip 到 x<26       ← 只有朝向屏幕的那条边
4. 细节         项圈 / 铭牌 / 内耳 / 前爪           ← 永远在光之上
```

`gLight` 是 `gradientUnits="userSpaceOnUse"` 的水平渐变（x 从 -2 到 42），三段：

| offset | 颜色 | 不透明度 | 作用 |
|---|---|---|---|
| 0 | `--wt-light` | 1 | 贴边最亮（屏幕就在左边） |
| .16 | `--wt-light` | .66 | 快速衰减 |
| .52 | `--wt-light` | 0 | 到身体中线消失 |

其中 `--wt-light: color-mix(in srgb, var(--wt-state) 78%, var(--wt-paper))`。

**为什么要混纸色**：屏幕色直接铺在近黑的剪影上，蓝光会变成"脏蓝"；混 22% 纸色提亮一档，才像光而不是像污渍。

**为什么必须 userSpaceOnUse**：默认的 objectBoundingBox 会让每个部件各自从自己的左边缘开始打光，头和尾巴的光向不一致 —— 这正是 03:04 版"贴纸感"的技术原因。

**朝向**：右栏工位（`data-side="right"`）把整个角色 `transform: scaleX(-1)`，轮廓光和屏幕光跟着镜像，与显示器的位置保持一致。一行 CSS，不动布局。

## 3. waiting 态的正确画法（几何规格）

**先说要避免什么**：把「头」单独旋转 15° 会在颈部产生一个剪切错位，读者的眼睛把这个错位读成畸形 —— 这是 03:04 之前那版的病根。**回头是上半身的事，不是头的事。**

**正确做法：整体 −6°，脸用三件东西"画"出来。**

| 要素 | 几何 | 32px 下 |
|---|---|---|
| 整体旋转 | `rotate(-6 32 58)` 作用于整个角色（含项圈、铭牌、前爪） | 肩线倾斜，一眼看出"转身了" |
| 眼睛 | 椭圆 `cx 19.8 cy 30.2 rx 3.3 ry 3.6`，纸色；瞳孔 `cx 20.4 cy 30.4 r 1.7`，墨色 | 3.3×3.6px，**可见** |
| 鼻梁凸起 | `M15.6 30.4 q-4.4 .4 -4 4 q2 2.2 4.8 1.2 z`，填墨色 | 凸出剪影 4 单位 ≈ 2px，**可见** |
| 眼睑线 | `M17 25.4 q3.4 -1.6 6.2 0`，1.2 宽，透明度 .5 | 只在 48px+ 起效 |
| 远耳 | **整只删掉**（不是旋转，是不画） | 剪影左右不对称 = 第三通道 |
| 近耳 | `rotate(10)` 向前倾 | — |
| 气泡 | 锚在**远侧耳朵上方**，右边缘对齐角色右边缘外 4px，底部距头顶 3px，带 3px 三角尾指向头顶 | 现有 `.bubble` 的 `right:-4; top:0` 就是这个位置，不用改 |

**露出几只眼：一只。** 两只眼 = 正脸 = 破坏"后脑勺"这个前提；零只眼 = 纯背身 = 读者不知道他在看我。一只眼 + 鼻尖凸起是唯一同时成立的解。

**为什么眼要画到 3.3px 那么大**（比真实比例大）：32px 下小于 2px 的东西会被抗锯齿吃掉。宁可大一点，也不能"看起来没有脸"。

## 4. 同 species 的身份：硬指标与实测

小审给的基线：`backend ↔ ops`、`pm ↔ frontend` 两对在 32px 下 **0.0% 差异、轮廓 IoU 1.0**，即逐像素相同。

**新的通道分配表**（每个角色至少动两样，同 species 的两两之间至少差三样）：

| 角色 | species | 体型 | 耳 | 尾 | 道具 | 头宽系数 |
|---|---|---|---|---|---|---|
| 阿策 pm | 猫 | std | 尖猫耳 | 卷尾 | 便签板（举高） | 0.94 |
| 小前 frontend | — | std | **耳机（无耳廓）** | 卷尾 | 键盘耳机 | 1.00 |
| 老后 backend | 狗 | **bulky** | 长垂耳 | 短粗尾 | 服务器灯 | 1.06 |
| 小审 reviewer | 狗 | **slim** | 短圆耳 | **无尾** | 放大镜 | 0.95 |
| 小研 researcher | 狐 | slim | 高狐耳 | 大蓬尾 | 书 | 1.03 |
| 小设 designer | 猫 | **slim** | **折耳** | 大卷尾 | 调色盘 | 1.07 |
| 老运 ops | 狗 | std | **立耳（截耳）** | **侧伸尾** | 扳手 | 1.02 |
| 笔笔 writer | 狐 | std | 短狐耳 + **浅色耳尖** | 低垂蓬尾 | 钢笔 | 0.98 |

**实测（S1 v2.1，32px 1:1 栅格，逐像素差 >24/255 记为不同）：**

| 同 species 对 | 差异 | | 跨 species 最低 6 对 | 差异 |
|---|---|---|---|---|
| researcher ↔ writer（狐） | **27.8%** | | ops ↔ writer | 22.3% |
| backend ↔ ops（狗） | 29.5% | | pm ↔ writer | 25.5% |
| reviewer ↔ ops（狗） | 29.9% | | researcher ↔ ops | 28.1% |
| backend ↔ reviewer（狗） | 30.1% | | designer ↔ writer | 28.1% |
| pm ↔ designer（猫） | 30.6% | | pm ↔ ops | 28.3% |
| pm ↔ frontend（猫） | 32.6% | | designer ↔ ops | 28.3% |
| frontend ↔ designer（猫） | 39.3% | | | |

**结论**：同物种 7 对 **27.8%–39.3%**，跨物种最低 **22.3%**（下限差 5.5pp）。跨物种里只有 2 对（28.3%）高于同物种最低那对 27.8%，而且两对都含 designer —— 它头最大（1.07×）+ 身最窄（slim），本来就和谁都不像。比 v2.0 的整体水平抬高了 5pp（手臂和尾巴加进来之后，剪影面积更大，差异更明显）。

复现方法：把 8 个角色各自渲染成 32×32 位图，两两算差异像素占比。§5 的验证图就是这个。

## 5. 每套的失败模式

| | 32px 可读性 | 暗色主题 | 实现代价 | 失败模式 |
|---|---|---|---|---|
| **S1** | **最好**：剪影 + 色块 + 光，全是大面积 | **最好**：只有墨色和光，光自动跟随 `--wt-state` | 最低：一个渐变 + 一个 clip + 一份几何 | 在 96px 以上会显得"平"，需要靠家具和屏幕光撑住画面 |
| **S2** | 与 S1 几乎相同（渐变在 32px 消失） | **最差**：高光点在暗色下变成白斑，必须把 `gHi` 的透明度从 .55 压到 .28，否则头上有块油 | 中：多两个渐变 + 两个高光层 | 亮色下"软"，暗色下"油"；同一份几何要维护两套高光参数 |
| **S3** | 最差：1.1 单位描边在 32px = 0.55px，渲染成灰雾 | 中：墨线在暗色下反而更清楚，但淡彩会灰掉 | 最高：每件家具都要勾边，且描边不能随缩放变粗（`vector-effect`） | 线越细越糊，线越粗越像贴纸；32px 与 96px 需要两套线宽 |

**S2 的暗色具体调法**（如果最终选它）：`gHi` 透明度 .55 → .28；`gBody2` 的 `--wt-ink-lift` 从 62% 纸色降到 45%；高光椭圆半径缩 20%。

### 图层契约（furniture-v2.svg）

```
z0 #u-floor      z1 #u-chair     z2 #u-monitor    z3 #u-spill
z4 角色（body / head 两个 group）
z5 #u-deskfront   ← 切掉角色下腹 8px
```

**踩过的坑**：`<use>` 的 shadow tree 里 **CSS class 选择器不生效**。第一版家具用 `.v-s1 .desk{fill:...}`，结果所有形状落到默认黑色。必须用自定义属性（`fill="var(--f-desk)"` + 在 `<g style="--f-desk:...">` 上赋值），自定义属性会继承进 shadow tree。

## 6.5 手臂与握持（v2.1 新增）

**为什么必须画手臂**：一块从肩膀直下的躯干 + 一个爪子，读起来是「图标」，不是「角色」。手臂是唯一能把人和桌面连起来的结构 —— 没有它，桌子是桌子，人是人。

### 几何

| 段 | 路径起点 → 终点 | 规格 |
|---|---|---|
| 远侧上臂 | 肩 (18.6, 49.4) → 肘 (13.6, 57.8) | 与水平约 **62°**，宽 5.2 → 4.4（向肘收） |
| 远侧前臂 | 肘 (13.6, 57.8) → 腕 (14.2, 64.4) | 与水平约 **85°**（几乎垂直落向桌面） |
| 远侧爪 | 圆角矩形 `x 14.6 y 62.4 w 11 h 7.6 r 3.8` | 压在桌沿（y=64）上 **1.6 单位 ≈ 2px** |
| 近侧上臂 | 肩 (45.4, 49.4) → 肘 (50.4, 57.8) | 镜像，62° |
| 近侧前臂 | 肘 → 腕 (49.8, 62) | 85°，但**停在桌面之上**（不落到桌沿） |
| 近侧爪 | 圆角矩形 `x 41.4 y 55.4 w 11 h 7.6 r 3.8` | **握道具**，与道具重叠 2–3 单位 |

- **爪子颜色**：`color-mix(in srgb, 墨色 48%, 纸色)`，比身体亮约 50%。这是全图唯一比身体亮的部件 —— 因为爪子朝向桌面、被屏幕光扫到。
- **爪形**：平顶 + 圆底（`M15.6 61.8h10v3.6q0 4.4-4.4 4.4h-1.2q-4.4 0-4.4-4.4z`），不是圆角矩形。圆角矩形的 3.8 半径在 7.6 高的形状上等于一个正圆 —— 这就是小审在 96px 里看到的「两枚硬币」。
- **接触**：两只爪子整块收在躯干轮廓内（x 15.6–25.6 / 40.4–50.4，躯干底边 x 13–51），只在底边露出前半截；**与躯干重叠 6 单位**，不可能脱开。
- **跟随转身**：`#paws` 带 `data-part="paws"` 和**与 body 完全相同的 transform**（`rotate(θb 32 64)`）。它在 z6，但几何上属于身体 —— 少了这一句，waiting 转身时爪子会留在原地，看起来像掉了两个硬币。
- **两段之间的折点**：上臂和前臂是两条独立 path，在肘部重叠 1.5 单位；不画关节圆，靠重叠出折角。
- **为什么近侧爪停在半空**：它要握东西。只有远侧爪落在桌沿，这是「一只手扶着桌、一只手拿东西」的自然姿势；两只都压在桌上，就没手拿道具了。

### 握持关系（v2.1 的核心修正）

道具不再「贴在身侧」，全部围绕近侧爪 (47, 59) 组织，与爪子重叠 2–3 单位：

| 角色 | 道具 | 握法 |
|---|---|---|
| 阿策 | 便签板 | 板的下缘 y=58 落进爪子（爪顶 y=55.4，重叠 2.6） |
| 小前 | 耳机 | 戴在头上，耳罩**取代耳廓**（这是它唯一的剪影特征） |
| 老后 | 服务器灯 | 机箱右缘 x=61.2 压在爪子右缘（重叠 2） |
| 小审 | 放大镜 | 手柄下端 y=59.4 落进爪子 |
| 小研 | 书 | 摊在桌面上，**两只爪子各压一个上角** |
| 小设 | 调色盘 | 盘右缘压进爪子 |
| 老运 | 扳手 | 柄下端 y=59.6 落进爪子 |
| 笔笔 | 钢笔 | 笔杆下端 y=58.8 落进爪子 |

## 6.6 data-part 契约（小审 V5 要读的钩子）

每个状态格子必须能被程序读到结构，不能是一整块 `<g>`：

| 钩子 | 数量 | 说明 |
|---|---|---|
| `[data-part="head"]` | 1 / 格 | 带 `transform="rotate(θh 32 44)"`，绕**颈关节**转 |
| `[data-part="body"]` | 1 / 格 | 带 `transform="rotate(θb 32 64)"`，绕**髋**转 |
| `[data-part="eye"]` | 1（仅 waiting） | 在 head group 内，跟着头转 |
| `[data-part="nose"]` | 1（仅 waiting） | 鼻梁凸起，在 head group 内 |
| `.bubble` | 1（仅 waiting） | 图纸里是锚点示意；移植时用 b.html 现有 DOM 气泡，class 名不变 |

**角度表**（head − body，V5 读的是差值不是绝对值）：

| 状态 | body° | head° | 差值 |
|---|---|---|---|
| idle / failed / provisioning | 0 | 0 | 0 |
| working | +1.5 | −3 | 4.5 |
| waiting | −4 | −12 | **8** |
| done | −1 | +5 | 6 |
| error | +2 | +7 | 5 |

**头形的「上宽下窄」怎么来的**：不是靠改 path，是靠**遮挡**。头的椭圆在 y=30 最宽（x14–50），项圈上移到 y=38.6，把 y>38.6 的部分全部盖住 —— 可见的头就是「宽顶 + 收进项圈的窄底」，加上 y=27–33 的腮毛，剪影自然上宽下窄。这比手改贝塞尔曲线稳，因为遮挡不依赖控制点的运气。

**为什么头绕颈关节 (32,44) 而不是头心转**：绕头心转会让人头和身体之间出现一个错位的缺口（上一版被判「畸形」的根因）。绕颈关节转时，头底边只在项圈里滑动 2px，项圈盖住它 —— 这正是「项圈压脖子 2px」的第二个用途。

## 8. 一句话交代设计意图

**32px 里能活下来的只有三样东西：剪影、色块、光。** 所以 S1 把全部预算押在这三样上 —— 头足够大所以剪影成立，项圈足够宽所以色块成立，屏幕光落在身上所以两者发生关系；其余一切都（质感、线、细节）只在放大的时候兑现，不参与 32px 的赌注。
